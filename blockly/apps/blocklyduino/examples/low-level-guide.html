Bits, AVR ports and bus drivers

Bits and AVR register tools are grouped under Low-level. For bus commands, use the left Add device button and choose Custom SPI device or Custom I2C device. Its named commands then appear at the top under Project devices.

Use bits for packed values, AVR ports for direct GPIO, and raw SPI/I2C commands for a device that has no ready-made driver. Put a reusable command sequence in a Function, with parameters for the values that change. Name a bus device once; its actions reuse the address or chip-select and SPI settings.

Start with the ordinary device blocks when they already provide the operation. Low-level blocks give you control over individual bits and protocol bytes. They do not automatically reduce RAM use.

Boolean logic and bitwise logic

A Boolean describes true or false. A bit mask describes several independent flags inside one integer. Use a Boolean condition for if; use bit operations to build or inspect a mask. The existing Logic gate offers AND, OR, XOR, NAND, NOR and XNOR. Boolean XOR means exactly one input is true; XNOR means both inputs have the same truth value. The bitwise versions apply that rule separately at every bit position.

OperationExampleResult
Boolean AND4 && 2true: both values are nonzero

Bitwise XOR6 ^ 24: toggles the selected bit

Select the width that matches the data: uint8_t is 0–255 with bits 0–7; uint16_t is 0–65535 with bits 0–15; uint32_t is 0–4294967295 with bits 0–31. Bit 0 is the least significant bit. A one-bit mask for bit 5 is 32, written 0x20 or 00100000.

The width-aware blocks keep results within that unsigned width. AND selects bits; OR sets them; AND with an inverted mask clears them; XOR toggles them. Use replace for one bit and insert for a contiguous field. To change arbitrary masked positions, combine (old & ~mask) | (new & mask). Extract/insert fields and join/split bytes help decode a sensor register or assemble an address. These value blocks return a result; assign it to a variable to keep the change.

The integer arithmetic block performs unsigned addition, subtraction, multiplication, integer division and remainder at the selected width. Overflow wraps; division discards the fractional part. A zero divisor returns zero. Use ordinary Math blocks for calculations that need fractions.

For shifts, a negative count or a count at least as large as the width returns zero. Rotations wrap modulo the width. An invalid bit index gives mask zero or test false; a set/clear/toggle leaves the width-truncated value unchanged. Field counts are clipped at the top of the selected width. Inputs are integers.

On this AVR, ordinary int is only 16 bits. In handwritten C++, use an unsigned 32-bit starting value such as 1UL << 31; 1 << 31 is not a valid substitute. Cast before shifting. The width-aware blocks handle these conversions for you.

For the D13 LED, make PB5 an output and set/clear PB5 in PORTB. For a button between D2 and GND, make PD2 an input with pull-up; a pressed button reads LOW. Reading PORTD reports its latch, not the button level. Use PIND.

Mask operations preserve the other bits. A whole-port write changes every bit, including pull-ups on input pins. Toggle writes exactly PINB = mask; do not replace this with PINB |= mask, which can toggle additional high inputs. Microchip ATmega328P, I/O ports.

Interrupts, volatile and special registers

volatile makes each required read or write observable to the compiler. It does not make a 16/32-bit variable atomic on an 8-bit MCU. If an interrupt changes a multi-byte value while the main code reads it, the result can mix old and new bytes.

Use the atomic statement around a short shared-data operation. It restores the previous interrupt state on exit. A read-modify-write such as “read port, change one bit, write port” can also lose an interrupt's update to another bit. Constant single-bit operations may compile to one AVR instruction; arbitrary masks need not. Keep delays, Serial transfers and I2C operations outside atomic sections. Do not use break/continue to escape an enclosing loop from inside atomic: its implementation has its own hidden loop. avr-libc atomic blocks.

Clear interrupt flags writes a mask directly to a write-one-to-clear register. For example, writing only the TOV0 bit clears that pending Timer0 flag. Using flags |= mask can acknowledge other pending flags too. Other registers have different rules: UART receive flags are not cleared the same way. Follow the selected register's datasheet; ordinary bit set/clear is not a universal register operation. Microchip interrupt flags.

GPIO and peripherals share pins

A timer generating PWM, SPI, serial or I2C can control a pin instead of its GPIO latch. A direct PORT write does not automatically stop PWM. Arduino's digitalWrite() explicitly disconnects PWM for the chosen pin before writing it. Arduino AVR digital I/O implementation.

Changing Timer0 configuration can change millis(), micros() and delays. Servo and tone libraries also use timer resources. Assign each pin and timer one clear owner. Avoid direct writes to D11–D13 while an SPI device is using them, or D0/D1 during serial communication. Arduino AVR timing implementation.

Speed, flash and RAM are different measurements

Direct port operations can remove pin lookup, PWM handling and function overhead. A compiler can also optimize ordinary calls when pins and values are constant. The result depends on the core, optimization settings and surrounding code. The Arduino pin lookup tables already live in flash; replacing their use does not automatically free SRAM.

Instruction timing in those compiled sketches

The direct HIGH and LOW operations each compile to a two-cycle SBI/CBI instruction: 0.125 µs at 16 MHz. The corresponding standard D13 paths take 53 cycles for HIGH and 51 for LOW, including argument loading and the call: 3.3125/3.1875 µs. These counts come from this compiled binary and exclude interrupt delays; they are not oscilloscope measurements.

A nop takes one CPU cycle (62.5 ns at 16 MHz); a loop around it has more instructions. Delays and function calls add overhead, and interrupts add jitter. Use a logic analyser or oscilloscope for actual waveform timing. Compiled instruction inspection establishes what the CPU executes, not the measured electrical rise time. Microchip AVR instruction set.

Build a small SPI or I2C driver

Start with the chip's command table, electrical levels, timing and address format. Put fixed wiring and bus settings in one named device. Put a complete operation such as readStatus in a Function; make register address or payload its parameters. Return the useful value or a status that the caller can check. A bus protocol alone does not define the chip's commands.

SPI

  1. Define SPI device with CS, mode, maximum clock and bit order.
  2. Use its transaction body. This applies its settings and holds CS LOW until the body ends.
  3. Send the command and address bytes. To read, exchange a dummy byte and use the returned byte. The correct dummy value and number of dummy cycles come from the chip's datasheet.
  4. Finish the body normally so CS returns HIGH. Do not nest transactions or leave the body with return/break.

Hardware SPI sends and receives simultaneously. On a 16 MHz ATmega168/328P its available clock rates run from 125 kHz to 8 MHz, in discrete divisions; a request below 125 kHz cannot be met by that hardware implementation. The transaction is not an interrupt lock. Multiple devices share MOSI/MISO/SCK and use separate CS pins. Arduino AVR SPI implementation.

I2C

Use I2C bus settings in setup and check its Boolean result. At 16 MHz this helper accepts integer clocks from 30419 to 400000 Hz; unsupported values return false without changing settings. Start with 100000 Hz and a 25000 µs timeout. A zero timeout disables it. The divider can round intermediate clock requests.

  1. Define I2C device with its 7-bit address, for example 0x68. Do not include the read/write bit.
  2. For a register read, begin write, queue the register-address byte(s), then check end write → status. Zero means success.
  3. Where the chip requires a repeated START, end that write with STOP=false, then immediately request the response with STOP=true.
  4. Check request → received count, then consume the returned bytes. A read from an empty buffer returns -1.

AVR Wire has 32-byte buffers. Queue/request only a bounded chunk; consume a response before requesting from another device. Wire's buffers and clock are shared even when the dropdown names differ. Do not interleave device operations or call Wire inside an ISR/atomic section: its blocking transfers need interrupts. If more than 32 bytes are queued, end-write status is 1, but the first 32 bytes may already have been sent. These raw operations do not infer register width, byte order, EEPROM page boundaries or a device's busy time. Arduino AVR Wire implementation.

When to bit-bang

Direct pin operations can implement a custom serial protocol or use different pins, as in the 74HC595 example. You must implement the clock edge order, data setup/hold times and any acknowledgements. Software timing depends on the complete generated code and interrupts.

For ordinary I2C, SDA/SCL are open-drain signals with pull-ups: drive LOW or release the line, rather than drive HIGH. A complete implementation must also handle START/STOP, ACK/NACK and applicable clock stretching. GPIO blocks are building pieces, not a complete replacement I2C library. NXP I2C specification.
