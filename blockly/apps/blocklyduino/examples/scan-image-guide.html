Examples · Plotter messages and controls

Move continuously; build the image on the computer

Example 61 — Continuous photocell scanner moves a light sensor with two positional servos. Pan sweeps smoothly across each row. Measurements are scheduled through that sweep; the servo does not stop for every pixel. Choose one-way rows or alternating forward/reverse rows.

  1. Connect the signals below and arrange a small, unobstructed servo travel range. A light-dependent resistor needs a voltage divider; connect its midpoint to A0.
  2. Open example 61, inspect the green Parameters area, and upload. Open Plotter, choose the serial port and 115200 baud, then Connect → Start.
  3. Watch the image and ADC chart. Move a light source, change one control, and watch the new scan. Stop holds the last commanded servo position. Save PNG saves the visible image.

Servo powerSuitable servo supply, with its GND connected to Arduino GND

On upload/reset both servo outputs begin at 1500 µs, so the servos may move to their centre position before Start. Start begins the scan. Both signals use Timer1 hardware PWM at 50 Hz. Pulse edges are generated by the timer; the loop updates the desired pulse width every 5 ms. Timer1 is reserved by these two outputs. Pulse widths are whole microseconds, within the configured 544–2400 µs calibration; your mechanism may need a much narrower range. Arduino’s Servo reference explains servo pulse commands; this example selects the workbench’s hardware PWM engine.

Commanded position is not measured position. There is no encoder or servo-arrival feedback. Samples are assigned from the planned trajectory. Motor lag, backlash, the optics and the light sensor’s response limit useful speed and detail. Slow the row sweep if the image stretches or differs between alternate rows. More image pixels do not create more mechanical precision.

Parameters you can change

The initial values are ordinary named variables in the green area. The same variables supply the live controls and the header. Use Areas → Parameters to focus these settings, or wheel-zoom around the pointer. Expand one function at a time to study the program; internal coordinates and timers are in a separate grey area.

Image width / imageWidth
Image height / imageHeight		Start with 32 × 24. Select higher resolution directly: if the current row is too fast for ADC/Serial throughput, its time automatically increases and the header shows the applied value. One column or one row is supported; width must exceed Skip line start pixels.
Scan both directions / bidirectionalChecked (1): alternate forward and reverse rows. Unchecked (0): every row scans from Pan start to Pan end; the return trip takes Between-row move time and collects no image data.
Skip line start pixels / skipPixelsInitially 0. Try 1, then 2 while watching alternate-row alignment. Sampling starts this many pixel periods later and all subsequent samples keep that delay, but their original image coordinates remain. Thus no image columns are discarded. At the row end, the servo holds until the delayed final readings arrive. The range is 0 through width−1; reduce skip first if you need a smaller width.
Time per row / sweepMs3000 ms means one full pan sweep takes three seconds. Increase it for slower mechanics or more samples/columns. This controls speed independently of resolution.
Samples per pixel / multiSamplesAverage several ADC readings spread through each pixel cell while pan keeps moving. Try 1, then 4 or 16. The maximum follows the available time; it is not fixed at 32.

Light offset / offset		corrected = average × gainPercent / 100 + offset. Gain 100% and offset 0 leave the reading unchanged; 125% means 1.25×. One-percent steps retain 0.01× multiplier precision without a floating-point command parser on ATmega168. Offset is signed ADC counts.

White signal / signalHigh		Corrected values at or below Black become black; at or above White become white. The initial range is 0–1023. Narrow it to use more image contrast from a weak signal. Black must remain below White.
Brightness levels / brightnessLevelsChoose 2–65536. Output is 0 through levels−1; 1024 levels use 0–1023, and 65536 use 0–65535. The pixel value is stored as uint16_t. This is output scaling, not extra ADC resolution.
Pan start/end / panStartUs, panEndUs
Tilt start/end / tiltStartUs, tiltEndUs		Four independently editable pulse widths. Reversed endpoints reverse that physical axis. Pan starts at 1100–1900 µs, tilt at 1200–1800 µs. Use a small range first. A one-row image uses the tilt midpoint.
Between-row move / transitionMsInterpolate from the held pose to the next row. Also used to return from the last row to the first and after changes. Start with 250 ms.
Row settling / settleMsExtra wait after the row transition, initially 100 ms. No measurements are assigned during transition/settling, and neither uses delay(). There is no per-pixel settling pause.

Accepted changes hold the last pulse widths while transmitting a fresh header, explicitly clear the image with @image-clear scan, then restart from row zero through the transition. Invalid values leave the previous parameter intact, restore its control value and pause with a message. Higher resolution can lengthen Time per row automatically; it never silently accelerates the mechanism. To scan faster, reduce columns or samples first if the shown minimum requires it.

Alignment example: at width 40 and 4000 ms per row, one pixel period is 100 ms. Skip 2 delays measurements by 200 ms in either direction while preserving x coordinates. This approximates a fixed sensor/mechanical lag; it cannot measure or completely correct arbitrary backlash. Row settling is different: it waits before movement starts. If no skip value aligns the rows, slow the sweep or turn off Scan both directions.

Ordinary Serial messages

announcePlotter contains a normal Serial template. Its connected variables fill {{imageWidth}}, {{imageHeight}}, intensity maximum and every control value/bound at runtime. The header is sent on boot, on START, and after accepted changes. No JSON parser is needed on Arduino.

@plot {"version":1,"id":"photocell","fields":[{"id":"adc","min":0,"max":1023}],"widgets":[{"type":"image","image":{"id":"scan","width":32,"height":24,"mode":"gray","max":1023}},{"type":"line","fields":["adc"]}]}

The full example’s header also defines the 17 controls. publishPixel sends coordinates/intensity plus the short ADC CSV line for the chart. For example, changing gain sends @set gain 125 back to the board; readPlotterCommand validates the complete number before changing gainPercent. @set both 0 selects one direction; @set skip 2 delays sampling by two pixel periods. Other sketches can reuse these same generic template/command blocks for entirely different data.

A repeated coordinate replaces that pixel only. An unchanged completed raster starts again without clearing old pixels. Fit fits the configured image into the available screen. PNG uses 8-bit channels; use Plotter capture for raw higher-depth pixel values and configuration revisions. Example 75 demonstrates RGB messages without extra hardware: "mode":"rgb" and @pixel imageId x,y,r,g,b.

What limits the speed?

The computer accepts dimensions up to 16384 per side and 16 megapixels in total. The AVR stores only coordinates, accumulated samples, timers and a bounded command line. Increasing image size does not allocate a framebuffer on Arduino.

The Pro Mini ADC returns 10-bit readings, 0–1023; see Arduino’s analogRead reference. The program budgets at least 250 µs per conversion plus loop work. sampleSum is 32-bit, allowing up to 65535 readings per pixel without overflowing. Sampling times are centred in each pixel cell and remain independent of the 5 ms motion-update schedule.

At 115200 baud, one byte consumes ten wire bits. The worst pixel plus ADC record is 35 bytes at the supported coordinate/value sizes; the example budgets 45 bytes and a further 50% time margin: ceil(45 × 10 × 1000000 / 115200 × 1.5) = 5860 µs per pixel. ADC and UART budgets determine the live resolution/speed/averaging limits. If added work still makes sampling fall a full interval behind, the example stops with a timing-overrun message instead of assigning late readings to old positions.

Row, transition and settling controls each allow up to 2147483 ms. Skip is smaller than image width, so the sweep plus delayed readings remains shorter than one full 32-bit microsecond counter wrap. Unsigned elapsed-time subtraction survives rollover. Physical servo speed and sensor response usually impose a lower useful speed than the electronic limits.
