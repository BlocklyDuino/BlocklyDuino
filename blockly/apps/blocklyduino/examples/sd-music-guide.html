Music guide

One note, a sequence, or a polyphonic score

Shared pitch format

Use A–G plus an optional # or b and an octave: C4, F#5, Bb6. A numeric pitch is Hz, e.g. 440. R (or rest in the record parser) means silence. Supported sound frequencies are 20–4000 Hz; unsupported notes are rejected. Duration is 1–60000 milliseconds.

C4 250
F#5,100
R 100
440 500

play note record accepts one record from a String variable or null-terminated char array, including text read from SD or EEPROM. It starts a note and returns immediately; trigger it once when busy is false. Invalid input leaves the existing sound unchanged.

Example 39 opens MELODY.TXT, reads one bounded line into a variable and passes it to play note record. The last-operation-OK test rejects failed/overlong reads. Example 68 demonstrates a text variable without an SD card. The older play score → sequence · one voice format also streams whitespace-separated note/duration pairs with a 32-character read budget.

Timed polyphonic records

Example 69 maps voices 1, 2 and 3 once to three named passive buzzers. Copy POLY.TXT to the root of a FAT16/FAT32 card. Select a timed format in play score and call service score on every loop pass, without delays.

@score 1 absolute
# time_ms, voice, pitch, duration_ms
0,1,C4,250
0,2,E4,500
0,3,G4,500
250,1,F#5,250
500,2,R,100
500,3,440,100

absolute: time is milliseconds since start. Records must be in nondecreasing time order. Equal times start overlapping voices; a new event on the same voice replaces its previous note. A rest silences that voice for its duration. delta: time is the interval after the previous event, not after that note finishes. Zero adds another event at the same time. The header is optional (default absolute) and must precede notes.

@score 1 delta
0,1,C4,500
0,2,E4,500
0,3,G4,500
500,1,C5,250

Comma, tab and whitespace separators work. Each timed event occupies one line; LF and CRLF are accepted. Comments start with # outside a pitch token and may be arbitrarily long. Event/header lines are limited to 39 stored characters. Times and cumulative delta times must be 0–2147483647 ms. A final line without newline is valid. Missing voices, bad pitches, invalid durations and decreasing absolute times stop the score and make score OK false.

Timing and memory

The parser reads at most 32 characters per service call and buffers one event, not a whole song. Call it frequently; SD access or a slow loop can delay note starts. Same-time records are dispatched across a few service calls if they exceed the read budget. With the AVR IRQ engine, Timer2 independently generates and expires three voices while Timer0/millis remains available. Hardware outputs generate the waveform autonomously; AVR/STM32 hardware note expiry is serviced from loop and can be delayed by blocking I/O. This is cooperative scheduling, not a hard real-time guarantee.

The file format is independent of the selected buzzer engine. Map each voice to a named hardware or software buzzer, including mixed engines. The editor checks their pins and timers. On ATmega168/328, SD reserves D11/MOSI so hardware sound can use D9/Timer1; two additional software voices may share Timer2. That mixed SD variant is larger than the software-only example and needs ATmega328P rather than the standard ATmega168 bootloader space. See pulse engines and timing limits.

The player owns the card's one open file until EOF/stop/error. Do not use that same file for image creation/logging during playback. Playback remains active through the last sounding note/rest. Stop closes the file and stops the mapped voices. Timed playback works across millis rollover.

On ATmega168 the SD cache and three voices leave little stack headroom; keep the example small. ATmega328P provides twice the RAM. Compilation and host simulations do not verify a particular card's latency or the wiring of physical buzzers.
