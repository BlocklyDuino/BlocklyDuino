Editor guide

Prepare a frame, then send it

  1. Add the display or strip once through Add device.
  2. Declare an array under Variables with the required element type and shape.
  3. Build its contents using set array [index]. These operations change RAM only.
  4. Choose the device's send buffer action. Connect Variables → array, which passes the entire array without copying it.

Draw a custom 5×8 LCD symbol

  1. Add an I2C LCD and choose its address, columns and rows once.
  2. Declare a byte[8] array. Each element is one row, top to bottom. Values 0–31 use five bits; bit 4 is the leftmost dot.
  3. Use the named LCD define glyph action. Connect a slot number (0–7) and the whole row array.
  4. Use show glyph for one position, or place the slot number in a char/byte display-buffer cell and send the buffer in raw codes mode.

The eight rows above make a face. Example 72: two faces chase through an 80-byte buffer shows all steps in editable blocks. Slot, column and row sockets accept variables. All eight slots, including 0, work in raw-code buffers. Fill blank cells with 32; zero is a glyph, not a terminator. Text mode still turns zero into a space for saved older projects.

CGRAM holds eight definitions for the whole display. Reusing one slot in many cells costs no extra glyph slots. Redefining a slot changes every visible copy of that glyph. Create definitions in setup unless an animation deliberately changes them. Invalid slots/coordinates are ignored; only the lowest five bits of each row are drawn. The helper copies eight temporary row bytes, never another complete frame.

Dimensions and RAM

Indices start at zero. Dimensions are compile-time constants; indices and pixel values can be variables or expressions. A 128×64 OLED frame needs 8192 bytes as byte pixels, or 1024 bytes packed. ATmega168 has only 1024 bytes for the entire program's RAM, so use a small tile there. A 128×160 RGB565 frame needs 40960 bytes; use a larger MCU such as RP2040. Nothing silently allocates an extra full frame.

Example 65 sends a 128×8 tile (128 bytes) to a 128×32 display; change shape to 4,128 and the page loop to 0..3 for the full frame on a larger AVR. Example 67 uses an 8×8 tile. Smaller buffers update the top-left region and preserve pixels outside it. OLED partial edge tiles zero-pad their unused pixels.

Physical LCD/OLED/TFT data still crosses a serial bus sequentially; one block does not guarantee a display-side atomic page flip. NeoPixel values are latched by show. Finishing the RAM buffer first avoids interleaving your calculations with display writes.
