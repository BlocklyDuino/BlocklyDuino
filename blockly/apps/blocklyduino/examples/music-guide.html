Beeps, melodies and three voices

Choose an engine on each passive buzzer definition. The IRQ engine described below provides three AVR voices on ordinary GPIO. Hardware waveform mode uses timer outputs on AVR/Blue Pill or PIO on Pico, without a per-edge software interrupt. The same notes and SD scores work with either engine; Connections shows compatible pins and shared resources.

Add a Passive buzzer with Add device in the left sidebar and give it a name and pin. Its Notes and Melodies sections appear under Project devices. Music actions use that name. Up to three buzzers can play different pitches simultaneously on a Pro Mini ATmega168/328P. No delay block is required.

Connect the outputs

The three-voice example uses D4, D5 and D6. Connect each pin through a 100–330 Ω series resistor to its own small passive piezo, with the other terminal connected to GND. Keep SPI pins D11–D13 and the usual SD chip-select D10 available for storage.

A passive piezo follows the generated pitch. An active buzzer has its own oscillator and cannot reproduce the melody correctly. A low-impedance speaker, such as an 8 Ω loudspeaker, needs a suitable driver or amplifier; it is not a direct GPIO load. Do not join the three GPIO outputs together. A single speaker requires a resistor mixing network and an amplifier.

Start a note once

speaker play Hz for ms starts a note and returns immediately. Put a pitch block such as A4 into the Hz socket, or use a frequency calculation. Use rest for a timed silent interval, busy to check whether playback continues, and stop to cancel it.

Calling play on every loop pass keeps restarting the note. Trigger it from a button event, setup, a timer or an “if not busy” condition. A new note replaces that buzzer’s previous note or melody.

Supported frequencies are 20–4000 Hz and durations are 1–65535 ms. Frequency 0 is silence; duration 0 stops. The library clamps values outside these ranges. The pitch dropdown stays within the supported range.

Build a melody in blocks

  1. Add a Melody definition beside setup and loop.
  2. Put note/rest items inside it. Select a pitch and a duration for each item.
  3. In setup or an event, choose speaker play tune once/repeat.
  4. Put update melodies near the start of loop. It services all three voices.

Each melody item occupies 4 bytes of program flash, not RAM. The same melody can be played by different buzzers. Each voice has its own playback position, so three separate melodies can run together.

Single-note duration ends in the interrupt, even when loop is busy. Moving to the next melody item happens during update melodies or busy. A slow SD operation can therefore add a gap before the next note; it cannot make the current note continue indefinitely. Keep loop responsive when exact musical rhythm matters.

Which timers are used?

TimerUse with these blocks
Timer0Unchanged: Arduino millis(), micros() and delay() retain their timebase.
Timer1Available to Servo or another compatible library.
Timer2Shared by all three music voices. Core tone/noTone, IRremote’s default receiver timer and PWM on D3/D11 conflict. The generator rejects these known block combinations.

Three hardware timers can produce three voices: Playtune supports that arrangement on ATmega168/328. Its third voice takes Timer0 and disables normal millis/delay timing. The IRQ engine instead shares one timer so sensors, servo control, SD and ordinary program timing remain usable. Playtune’s timer documentation

Arduino’s ordinary tone() supports one simultaneous tone and interferes with PWM on D3/D11. Timer0 provides the Arduino timebase. Arduino tone reference · Arduino timer/PWM documentation

SPI communication remains available. Libraries that disable interrupts, such as NeoPixel show(), can cause clicks and stretch note timing. Other interrupts can add edge jitter. Custom C++ or libraries can also claim Timer2; the block checks cannot detect every external timer user.

SD melody files

The SD melody blocks stream note text from a known file, using the existing named SD card and a named buzzer. They do not load the whole song into RAM. Keep the SD melody update call in loop. Use either a file melody or a flash melody on a given buzzer at a time. The card’s existing file handle is shared, so do not open or write another file on that card during playback.

Implementation and verification

The installed BlocklyMusic helper uses a 15,625 Hz Timer2 interrupt and 16-bit phase accumulation to generate square waves. Edges fall on a 64 µs grid. Finite-note expiry has approximately 1 ms granularity, plus any delay caused by another interrupt. This is suitable for piezo melodies and effects; it is not sampled audio playback. The interrupt shuts off while all voices are idle.

The hand-written three-voice melody plus a millis-based LED indicator compiles to 2548 bytes of flash and 72 bytes of global RAM on ATmega168 at 16 MHz. The actual generated Blockly examples also compile: 38a beep 1758 bytes flash/48 bytes RAM; 38b three voices 2492/72; 38c melody with rests 2282/54. XML save/reload and device renaming preserve their generated code and references.

A host test runs the actual library logic with simulated AVR registers. Over 15,625 interrupt calls, 440/660/880 Hz voices produce 880/1320/1760 edges. It checks independent note expiry, rests, delayed melody servicing, stop and channel limits. A static count of the compiled AVR ISR gives a worst path of 300 CPU cycles including interrupt entry and vector jump: 18.75 µs at 16 MHz, within the 64 µs sample interval. This is an instruction-based bound, not an oscilloscope measurement; it excludes time spent in another interrupt before this ISR starts. Normal three-voice processing is roughly 14–16% CPU at 16 MHz, depending on pitches and note transitions.

The source is included under libraries/BlocklyMusic. Its public API is BlocklyBuzzer(pin), begin(), note(hz, ms), rest(ms), stop(), busy(), play(PROGMEM_score, count, repeat) and BlocklyBuzzer::updateAll(). Current hardware support is ATmega168/328P at 8–24 MHz clocks divisible by 125 kHz. Physical sound and wiring have not been tested by this installation.
