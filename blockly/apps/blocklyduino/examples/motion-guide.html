Motion, pulse engines and timer resources

All examples · Timer1 speed control · Potentiometer and continuous ramp

Define a STEP/DIR stepper once, choose its engine and motion, then use the named actions. The engine determines which pins work and who generates pulses. A speed value is a requested rate in driver pulses per second, including microsteps; it is not revolutions per minute.

Does continuous test mode use acceleration?

Yes: choose continuous with acceleration and set acceleration in steps/s². Signed speed is a target and zero ramps down. Instant speed on the loop engine changes the target immediately and deliberately does not apply acceleration. Position moves accelerate/decelerate through run; the Timer1 engine handles its queue itself. Example 62 demonstrates the loop ramp; example 70 demonstrates hardware-timed speed commands.

Speed, acceleration and smooth changes

Maximum speed is a ceiling. Signed speed is the continuous target: positive and negative choose direction, zero requests a stop. Choose continuous with acceleration to ramp toward it and brake before reversing. At 5,000 steps/s², reaching 30,000 from zero takes about 6 seconds, ignoring driver/load limits. The loop engine also offers instant changes without acceleration; the timer engine uses accelerated motion.

Example 70 starts stationary. Open Plotter at 115200 baud, Connect and Start. The sketch creates a signed speed input from −30000 to +30000 steps/s. Enter a value and apply it; the sign selects direction. Zero or Plotter Stop requests an accelerated stop. The graph shows the requested pulse rate, not measured shaft speed. Change acceleration in the device definition; no delay or run block controls pulse timing. STEP is D9 and DIR D4.

This hardware engine has a very tight Flash budget on ATmega168. Compile after any edit. Adjacent high-speed requests may map to the same timer period, so an input step of 1 does not imply physical frequency increments of exactly 1 Hz.

Requests may be integer or fractional, but physical timing is quantized. On a 16 MHz AVR, a Timer1 tick is 62.5 ns. Near 30,000 pulses/s, adjacent whole periods are 533 and 534 ticks: about 30,018.8 and 29,962.5 pulses/s. Several tiny target changes can therefore select the same period. This is much finer than a polled loop and its 4 µs micros() timebase, but it is not an exact arbitrary-frequency synthesizer. Clock tolerance also affects the rate.

A 10-bit potentiometer reading has only 1,024 levels. Mapping it from −30,000 to +30,000 already creates steps of about 59 pulses/s before timer rounding. Use a narrower range or coarse/fine controls for smaller changes. Acceleration smooths the transition; it cannot create extra ADC levels. Example 62 samples the potentiometer every 20 ms and services the loop engine continuously between samples.

For a 1.8° motor at 1/32 microstepping: 200 × 32 = 6,400 pulses/revolution. At 30,000 pulses/s that is about 281 rpm. Use your actual full-step angle and driver microstep setting.

STEP width and driver modules

The loop engine exposes minimum STEP pulse width in microseconds. Match the external driver's specification; older optoisolated CNC modules may need longer pulses than small A4988 boards. Example 62 uses 5 µs as an illustrative setting, not a universal TB6600 module specification.

The Timer1 library's STEP high phase is a few microseconds, ended by its interrupt. It does not offer a configurable AVR pulse width, so that field is hidden in Timer1 mode. The visible DIR delay is at least 40 µs. Confirm the actual module's pulse and direction timing; a module marked TB6600 is not necessarily electrically identical to the bare Toshiba chip. Long interrupt-disabled sections can stretch a high pulse or disrupt the queue even with hardware-timed rising edges.

Servo calibration

The AVR core Servo library stores endpoint offsets in signed bytes with 4 µs resolution. Its minimum request must be 33–1059 µs and maximum request 1889–2915 µs; for example 500–2500 is valid, but 2000–2400 is not. The editor rejects overflowing offsets and Connections reports the effective rounded endpoints. Hardware PWM has a wider calibration range and does not use this encoding.

Hardware Servo and sound

Example 71 uses a potentiometer on A0, hardware Servo on D9 and a passive buzzer on D11. Choose engine once in a device definition; its pin menu then shows that engine's compatible, available outputs. Existing XML retains its previous engine and wiring. A hardware engine can offer fewer channels than a software engine because each signal needs a real peripheral output.

Servo minimum/maximum µs calibrate both degree and microsecond actions. Defaults remain 544–2400 µs; example 71 uses 1000–2000 µs. Hardware refresh is configurable from 40 to 400 Hz, with the maximum pulse shorter than one frame. Use the actual servo's supported pulse range and refresh; these editor settings are not a claim that every servo supports 400 Hz. A repeated unchanged pulse setting does not reconfigure the peripheral.

The buzzer's hardware waveform engine uses the same note records, flash melodies and timed polyphonic SD format as the AVR IRQ engine. A score may mix both kinds of output. The generated loop services hardware note durations and melodies automatically. On AVR/STM32 a long blocking operation can prolong a note or delay the next note, even though its waveform continues without CPU service. Keep loop responsive for precise musical timing. The explicit update block still services the optional AVR software melodies.

Hardware pitch is rounded to an available timer period. AVR D11's 8-bit timer has a minimum around 31 Hz at 16 MHz (around 16 Hz at 8 MHz); lower requests stop that output and set waveform OK false. Use D9's 16-bit timer for lower pitches when free. The common text-score pitch range remains 20–4000 Hz. Independent hardware audio uses more timers, while the optional three-voice IRQ engine shares Timer2 and consumes CPU in a 15,625 Hz mixer interrupt.

The software pin checks use declared devices and supported blocks. Arbitrary C++ or direct register writes can bypass them. The Connections tab lists timing notes and resource conflicts. A generated/compiled sketch is not a measurement of motor speed, torque or lost steps.
