Interrupts: respond to pins and hardware timers

Open Interrupts in the left toolbox. The event blocks sit outside setup and loop. Define the source once, give it a name, and put the short handler inside. The generator performs the source setup automatically. Named enable/disable blocks refer to that source, so its pin is not repeated.

These blocks target the current ATmega168 / ATmega328P Pro Mini and Uno-style pin map. They do not silently pretend to configure STM32 or RP2040 interrupt hardware.

Pin events

INPUT_PULLUP is useful for a button from the selected pin to GND: released is HIGH, pressed is LOW. Choose INPUT for a signal with its own defined voltage. Pin input mode is configured early in setup. Automatic enabling runs after the user setup bodies; choose start disabled if you want to enable the source later yourself.

ModeMeaning
FALLINGHIGH → LOW; a pull-up button press.
RISINGLOW → HIGH; a pull-up button release.
CHANGEBoth transitions.
LOWExternal interrupt only. The interrupt can keep firing while the pin remains LOW; it is not a one-shot button event.

Use the named attach / detach action to control a source later, and its attached-state value when needed. Attach enables that source; detach disables it. Disabling one pin-change source does not disable the other declared sources in that port. Enabling does not manufacture an edge from the pin's current level. Very short pulses or multiple transitions during another handler can be missed; these blocks are not a hardware event queue.

A mechanical button may produce several edges on one press. The counter examples deliberately count electrical edges. For one logical event per press, use a debounced signal or set a flag in the handler and perform stable-level/debounce timing in loop. Waiting inside the handler is not a debounce method.

Attach and detach: control when a handler is active

Defining an event handler describes what to do. Attach begins listening to its configured pin and edge; detach stops listening. The handler block keeps the pin, edge and input mode in one place. In an action block, you select only the source name.

  1. Create an external pin interrupt named pulseInput, choose D2, FALLING and INPUT_PULLUP.
  2. Choose start disabled. The source is detached when setup finishes.
  3. Use pulseInput → attach at the point where measurement should begin.
  4. Use pulseInput → detach when that measurement should stop.

The attached value reports the source's hardware enable mask; it does not report the global interrupt-enable bit. Detaching a source does not clear your variables, remove its handler block or stop other interrupts. Edges that arrive while detached are not replayed when you attach again. For a LOW-level external trigger, a pin still LOW can trigger immediately on attachment.

Example 60 starts detached. Open Plotter at 115200, Connect and Start. Its own header creates the Attached checkbox, counter and Clear button. Connect a button between D2 and GND; the count changes only while Attached is checked. Detaching preserves the count; Clear deliberately resets it. Mechanical bounce may add several counts per press.

Pass data to loop safely

  1. Declare a shared variable outside all bodies. Choose volatile, for example volatile uint16_t pulseCount.
  2. Inside the interrupt handler, increment the counter or set a flag. Keep this work short.
  3. In loop, use atomic to copy the shared value to a normal local variable.
  4. After the atomic block, print, draw, save files or do other longer work using the copy.

volatile keeps accesses visible to the compiler; it does not make a 16- or 32-bit access indivisible on an 8-bit AVR. The atomic block restores the previous interrupt state on exit. For a pending flag, copying and clearing it in the same atomic block prevents an event being lost between the two operations.

volatile uint16_t pulseCount;

// Interrupt body: only record the event.
pulseCount++;

// In loop:
uint16_t snapshot;
ATOMIC_BLOCK(ATOMIC_RESTORESTATE) {
  snapshot = pulseCount;
}
Serial.println(snapshot);

Declare temporary variables inside the handler if only that handler uses them; they remain local. Do not put Serial printing, delay, I2C/Wire, display updates, SD operations, or unbounded loops inside a handler. Other interrupts normally wait while a handler runs; millis() cannot advance normally there. Direct port operations and bounded arithmetic are typical handler work.

Timer1 periods and control

The period socket is in whole microseconds and accepts a number, variable or calculation. It is evaluated during setup; the runtime period block reconfigures and starts the timer and returns success/failure. At 16 MHz, accepted periods are 1–4,194,304 µs. The smallest fitting prescaler is selected; the compare duration rounds upward to the next hardware tick. At the largest prescaler, one tick is 64 µs. These are configuration limits, not a promise that a one-microsecond C++ handler is practical.

Pause stops the timer clock and its interrupt while retaining the configured period. Restart begins a new full period rather than continuing an old phase. An invalid runtime period stops the timer and clears its configuration; restarting then has no effect until a valid period is set. The shared prescaler is not reset, so the first period after a restart can vary by up to one timer tick. Subsequent configured intervals follow the hardware compare counter.

Timer1 is exclusive. It conflicts with Servo and Timer1 PWM on D9/D10. The normal Arduino Timer0 used by millis()/delay() remains available. Raw register code or external libraries can also claim Timer1; the generator catches known combinations, not every possible C++ side effect.

Four examples

ExampleWiring and result
57 · External interrupt counterButton between D2 and GND. Falling edges increment a volatile counter. Loop takes an atomic copy and sends pulses:123 at 115200 baud. Contacts may bounce.
58 · Two pin-change countersOptional buttons from D4 and D5 to GND. Both sources share the port's vector; their individual counters are copied together atomically. Monitor/Plotter receives left:12,right:8.

Unsigned counters wrap at their type limit. Example 57/58 use uint16_t, so the count wraps after 65535; example 59 uses uint32_t. The examples are compiled for the installed ATmega168 profile; hardware pulse timing and electrical wiring must be verified on the actual connected circuit.
