Serial Plotter: one stream, many views

Open Plotter · Open Monitor · Grouped examples

The microcontroller sends ordinary text. The computer draws charts, gauges, bars, tables and images. One value can feed several instruments, and several values can share one instrument. The AVR needs no JSON parser, chart history or image framebuffer.

First success: no extra components

  1. Open 55 · Interactive LED lab and upload it to Pro Mini ATmega168 / 16 MHz. Its built-in L LED starts blinking.
  2. Open Plotter, choose the board’s port and 115200 baud, then Connect.
  3. Press Start. The board sends its dashboard, instructions and current settings. Change Blink interval, select Steady light, or send a short message. Watch the real LED and the graph.

No dashboard needs to be created on the computer first. The sketch announces its header in setup and repeats it on Start. Sensor/scanner lessons wait for Start before sampling; the LED lesson runs immediately. Stop pauses the lesson but leaves the shared serial connection open.

A fresh or reset Plotter waits for a header. Unannounced numbers do not create guessed charts. An explicitly loaded Manual profile is the alternative. If nothing appears, check that the uploaded sketch is one of these updated lessons and that both sides use the same baud rate, then press Start. Reset view clears the current automatic view; Start asks the board to describe it again.

The default Fit layout keeps the configured instruments visible in the available window. Choose Scroll in settings when you prefer larger instruments with vertical scrolling.

Build your own: three kinds of line

Start with one field and one view. Send the header once in setup and again when the complete command START arrives. Finish each line with Serial.println.

@plot {"version":1,"id":"light","title":"Light meter","description":"Turn the A0 potentiometer.","fields":[{"id":"adc","min":0,"max":1023}],"widgets":[{"type":"gauge","field":"adc"},{"type":"line","fields":["adc"]}]}
@msg Ready. Turn the knob and watch the gauge.
512
650

The first line defines the interface. The message tells the person what to do. Each later number is one ADC sample. This JSON is an ordinary Serial text block stored in Flash; click its message to edit formatted JSON. There is no JSON parser on the Arduino.

Where to find the blocks

Open Text & serial in the toolbox. Use serial text for fixed messages, or serial template when values come from variables. Click the compact message field to open the multiline editor. Write {{width}} in the message, save it, then connect the width variable to the new value socket. Repeated placeholders share a socket; {{gain:3}} requests three decimal places. The same block can send headers, samples, pixel coordinates or explanatory messages.

@plot {"version":1,"id":"meter","fields":[{"id":"light","min":0,"max":{{maximum}}}],"widgets":[{"type":"gauge","field":"light"}]}
@msg Current width: {{width}}
@pixel scan {{x}},{{y}},{{brightness}}

Each example above is a separate template ending in new line. Numeric placeholders are unquoted in JSON. Values print directly, so arbitrary text needs its own JSON quoting/escaping. The fixed parts stay in Flash and the values stream out; no full header is assembled in AVR RAM. Large headers take time to transmit, so send them at configuration boundaries, not between time-critical samples.

For incoming commands, put read serial lines in loop (or a function called from loop). Inside it, when command START handles an exact command; when number validates a number and updates a declared global variable. Its min, max and step sockets accept variables or expressions. Use its accepted branch to announce the new configuration, and invalid branch to explain rejection. The bounded receiver waits for a complete line without pausing loop. Lesson 61 shows these blocks together; expand readPlotterCommand, announcePlotter and publishPixel to edit the protocol.

Add controls the board can receive

The header’s controls array creates inputs. Copy one control first, then add the others you need. A control ID names the setting in messages; its label is shown to the person.

"controls": [
  {"id":"period","type":"slider","label":"Blink interval","unit":"ms","min":100,"max":2000,"step":100,"value":500},
  {"id":"duty","type":"number","label":"On-time","min":10,"max":90,"step":10,"value":50},
  {"id":"enabled","type":"checkbox","label":"Enable LED","value":true},
  {"id":"pattern","type":"select","label":"Pattern","options":[{"value":"blink","label":"Blink"},{"value":"steady","label":"Steady light"}],"value":"blink"},
  {"id":"message","type":"text","label":"Message","maxLength":40,"value":"Hello"},
  {"id":"restart","type":"button","label":"Restart cycle"}
]

The PC sends these ordinary newline-terminated commands only when the person changes/sends a control:

@set period 700
@set enabled 0
@set pattern steady
@set message Hello board!
@do restart

The sketch reads a full line, checks the ID and permitted value, then changes its variable or performs the action. Checkbox values are 1/0; text may contain spaces, but not newlines. Text limits count UTF-8 bytes, so the AVR can use a fixed byte buffer. The complete reusable parser is visible in lesson 55’s collapsed functions; it uses arrays and logic blocks, not String allocation.

Reply with the values the board actually accepted and a useful message:

@state {"period":700,"enabled":false,"pattern":"steady"}
@msg Steady light selected. Choose Blink to use the interval again.

A state reply updates existing controls without sending another command. Initial control values in the header must match the sketch; send @state after a header when current values differ. Step constraints apply from min. A slider sends its committed value, not a flood of intermediate commands. The sketch must still validate incoming commands; someone can also type them in Monitor.

For a rejected or adjusted setting, reply with that one control's actual value, for example @state {"width":32}, and an @msg explanation. The input then shows what the board applied. A later full header can update ranges and image geometry while keeping unrelated unsent edits. A numeric range with min equal to max displays its only possible value as a disabled control; widening the range enables it again. Missing confirmations time out visibly; sending a command alone is never shown as proof that the board accepted it.

A message-only dashboard 
@plot {"version":1,"id":"memory","title":"EEPROM result","description":"Write once, then read the test records.","fields":[],"widgets":[]}
@msg Stored value: 1234
Stored text: Hello

With this explicit message-only header, ordinary Serial.println output also appears in the recent-message log. Explicit @msg works with every dashboard. A header can include only a description and controls when no chart is needed. Messages are plain text, never HTML or executable commands.

Create or adjust a layout in Plotter

Open the dashboard builder, choose a starter, then edit fields, views and controls. Apply previews the layout; the header/code view supplies the text to put into the sketch. Saving a profile keeps a PC-side alternative; a controller-driven project should also keep its header in the program so another computer can display it. Advanced JSON is available when you need formulas or more specialised layouts.

Messages, one complete line each

MessagePurpose
@plot {JSON}Describe fields, instruments and images. A valid later header replaces the dashboard while the sketch keeps running.
@use saved-idChoose a profile already saved in this browser. Saves AVR Flash when a large header is unnecessary.
@data {JSON} or CSVOne complete sample of input fields, with optional stream ID/device timestamp.
@pixel image-id x,y,valueReplace one image pixel. RGB supplies red, green and blue instead of one value.

Finish each record with a newline; Serial.println does this. Use decimal points, not decimal commas. Fixed headers use the ordinary serial text block and stay in Flash through F(). Click the compact message field for a formatted JSON editor. The transmitted header remains one line.

Numeric input after configuration

512,300
515,302

With two numeric fields in the accepted header, these are two complete samples. Labelled readings such as light:512 reference:300 also work when the IDs match that header. Numbers never guess a fresh layout. Use Manual only when you deliberately want a saved or hand-built PC configuration to override the board.

Minimal header with PC conversion

@plot {"version":1,"id":"pot","fields":[{"id":"adc","min":0,"max":1023},{"id":"volts","unit":"V","min":0,"max":5,"derive":{"op":"formula","expr":"adc * 5 / 1023"}}],"widgets":[{"type":"line","fields":["adc"]},{"type":"gauge","field":"volts"}]}
512
650

Only adc comes from the board. Derived volts is omitted from data rows. The formula assumes a 5 V ADC reference; use the actual reference. Non-derived numeric fields can use scale and offset: displayed = raw × scale + offset. Raw input is retained in captures.

Explicit identity and timestamp

@data {"id":"pot","t":1250,"values":[512]}
@data {"id":"pot","t":1300,"values":{"adc":650}}

CSV/array order follows the header's non-derived fields. Object values use their IDs. All input fields are required per sample. A different explicit stream ID is rejected. The optional t is device time in milliseconds for derivative/integral calculations. Charts also offer received-time and sample-index axes.

Instrument recipes

Put these objects in widgets. Referenced fields must exist. Related traces with matching units work well together; unrelated quantities are clearer in separate instruments.

ViewWidget JSONBehaviour
Lines{"type":"line","fields":["a","b"],"min":0,"max":100}Overlaid traces. Omit bounds for automatic scale.
Gauge{"type":"gauge","fields":["a","b"],"min":0,"max":100}Several coloured needles on one dial.
Bars{"type":"bar","fields":["a","b"],"min":0,"max":100}Bars beside each other. Bounds use widget/field settings or automatic scale.
XY{"type":"xy","series":[{"x":"time","y":"a","label":"A"},{"x":"time","y":"b","label":"B"}],"xMin":0,"xMax":10,"yMin":0,"yMax":100}Multiple independent x/y pairs. All bounds are optional.
Raw values{"type":"raw","fields":["a","b","state"]}Table accepts numbers, strings and booleans. Numeric graphics need numbers.
Image{"type":"image","image":{"id":"scan","width":32,"height":24,"mode":"gray","max":1023}}Gray or RGB image held on PC, fitted to the visible area.

Single gauge/bar widgets may use "field":"a"; single XY may use "x":"a","y":"b". Field bounds apply after scale/offset. Widget bounds override display scale without discarding data. History controls numeric samples retained for drawing; a widget may keep fewer samples than its dashboard. History and capture are separate.

Image beside chart

@plot {"version":1,"id":"camera","fields":[{"id":"light","min":0,"max":1023}],"widgets":[{"type":"image","image":{"id":"scan","width":32,"height":24,"mode":"gray","max":1023}},{"type":"line","fields":["light"]}]}
@pixel scan 0,0,512
@data {"id":"camera","t":80,"values":[512]}
@pixel scan 1,0,700

Coordinates start at zero; pixels may arrive in any order. Repeating a coordinate replaces only that pixel. @image-clear scan explicitly clears one image. A new image configuration starts a new frame. With one image, @pixel x,y,value is a valid shorter form.

For RGB select "mode":"rgb" and send @pixel scan x,y,r,g,b. The positive max defines input intensity range, for example 255, 1023 or 4095. Display/PNG export uses 8-bit channels; capture raw pixel records to preserve higher input precision. Save image exports the currently retained frame. The older standalone @image format remains supported; image widgets let charts and images coexist. Scanner wiring and formats.

PC mathematics

Place derived fields after their sources. Later derived fields may use earlier derived fields; forward references/cycles are rejected. The MCU sends only the original inputs.

OperationField exampleMeaning
Formula{"id":"power","unit":"W","derive":{"op":"formula","expr":"volts * amps"}}Safe arithmetic, no JavaScript execution. Inputs already have scale/offset applied.
Window statistics{"id":"average","derive":{"op":"mean","source":"volts","window":8}}mean, rms, min and max over the latest 1–1024 samples.
Sum{"id":"sum","derive":{"op":"sum","source":"count"}}Running sum of samples, not a time integral.
Derivative{"id":"slope","unit":"V/s","derive":{"op":"derivative","source":"volts","time":"device"}}Change per elapsed second. First result is empty.
Integral{"id":"energy","unit":"J","derive":{"op":"integral","source":"power","time":"device"}}Trapezoidal integration in seconds. Watts integrate to joules; volts integrate to volt-seconds.

Formulas support + − * / ^, parentheses, pi, and abs/sqrt/sin/cos/tan/log/exp/min/max/pow/clamp. Formula trigonometry uses radians. Write [field-id] around a hyphenated ID. Units are explicit metadata, not automatic dimensional analysis.

Received time is the default; device time uses the MCU t field and avoids USB delivery jitter affecting intervals. Missing/duplicate/backwards timestamps break a timed segment rather than inventing an interval. Invalid mathematical results become gaps. An accepted new header or loaded profile resets calculations; invalid configuration/data leave the existing valid state intact. Example 74 changes the averaging window after five seconds without stopping the board.

Profiles and live changes

Send @plot again whenever the layout should change. It replaces instruments, clears numeric history and resets calculation state; following rows must match its new inputs. Save profile remembers a configuration in this browser; JSON export/import transfers it. Manual profile mode ignores incoming @plot/@use so your selection stays in charge. A reset in controller mode removes the old layout and waits for a new header. Choose Auto when the controller should select the dashboard.

Capture and export

Set how many upcoming records to retain, then press Start capture. Numeric samples and pixel updates both count. Configuration changes remain in the same capture, linked by revision IDs. Capture stops at the requested count, explicit Stop capture, or the 20 MiB memory limit. Pause view and rolling chart history do not erase captures.

JSONL contains chronological configuration, sample and pixel records. CSV uses a long table: kind, config_revision, received_iso, device_time, stream_id, field_id, value, raw, configuration_or_pixel, with one row per field. This preserves live layout changes. Export before closing the tab; capture resides in browser memory. Save image is a separate PNG of the current frame.

Limits that affect real projects

Protocol v1 allows 32 controls, 32 fields, 16 widgets, 10–10,000 history samples and 32,768 characters per line. At 115200 baud, 8N1 carries about 11,520 bytes/s including punctuation. Short CSV saves bandwidth; tagged data adds identity/time. Serial.print can wait when its transmit buffer fills, so a millis schedule is responsive but not a hard real-time guarantee. Use an appropriate pulse engine and modest data rate alongside motors.
