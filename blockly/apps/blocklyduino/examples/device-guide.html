Define a device once

Use Devices to give hardware a name and configure its wiring. Put this definition beside setup and loop. The matching action blocks then offer that name in a dropdown. They reuse the pins, address and model automatically.

  1. Add I2C LCD with Add device in the left sidebar. Name it display, select 0x27, 20 columns and 4 rows.
  2. Add display print under Project devices → display, and place it inside setup or loop. Supply text, column and row. No wiring fields are repeated.
  3. For a second LCD, add another definition with another name and address. Each action chooses the intended display.

Renaming a definition updates the labels of its existing actions. Saved projects keep those references. If a device is deleted, its actions warn that the device is missing; code generation asks you to select a declaration instead of using guessed pins.

Names start with a letter and can contain letters, digits and underscores. Give every device a unique name. Use Functions for reusable behaviour such as “show temperature” or “scan one angle”; the device definition owns the wiring.

Stepper motion must keep running

move to position sets a target. Put run in loop so it is called frequently. It sends each step when due and applies acceleration. A long delay, DS18B20 wait, LCD update or ultrasonic read can interrupt smooth stepping. Use millis-based timing and perform short pieces of work on each loop pass. For two motors, call both run actions on every pass.

stop requests deceleration. Continue calling run until steps remaining reaches zero. It is not an immediate power-off or an emergency stop.

Coordinates and shared buses

LCD and OLED text positions start at zero. TFT coordinates are pixels. Printing a shorter value can leave old trailing characters; clear the row or pad the new value with spaces.

On the ATmega168/328P Pro Mini, hardware I2C is SDA=A4, SCL=A5. Hardware SPI is MOSI=D11, MISO=D12, SCK=D13. SPI devices can share those bus pins; each needs its own chip-select pin. Displays also need their declared DC and reset connections. Other Arduino board families use their own hardware bus pins.

Pin menus follow the selected board, device engine and declared resource ownership. Bus lines can be shared by compatible I2C/SPI devices but not unrelated GPIO. D0/D1 are reserved when hardware Serial is used; Pro Mini A6/A7 are analog-only. Conflicts and timing notes appear in Connections. Timer1 stepper mode offers only D9/D10.

Memory and a scanning radar

The ATmega168 has 1024 bytes of RAM. These device blocks avoid allocating a full OLED/TFT framebuffer. The standalone ST7735 test already uses about 12.3 KB of the 14.3 KB sketch space available with this bootloader; combining SPI OLED and TFT tests exceeds that flash budget. An SD library needs additional RAM, so write measurements or image rows incrementally instead of keeping an entire bitmap in memory. See the storage guide for file and BMP blocks. The radar example starts with one servo, one range sensor and Serial output; add storage after the scan works.

The installed libraries used by these blocks are AccelStepper, FastAccelStepper, Servo, LiquidCrystal_I2C, U8g2 (U8x8), Adafruit ST7735 and ST7789 Library, OneWire, DallasTemperature, DHT sensor library, Adafruit NeoPixel and IRremote. Adding an Arduino library alone does not create Blockly blocks: a block definition and its code generator are also required.

Validation: generated sketches for every listed device family were compiled for Arduino Pro Mini, ATmega168, 16 MHz. These are software compile checks; hardware behaviour depends on the connected module and wiring.
